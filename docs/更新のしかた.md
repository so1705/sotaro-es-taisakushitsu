# 更新のしかた（配布者用）

2週間に1回くらいを目安に、まとめて更新する。

1. 中身を直す（knowledge/・.claude/・interview/ など）
1-2. `python3 scripts/build-free.py` を実行して、無料版のファイル（free/アップロード用/）を作り直す
2. `VERSION` を今日の日付に変える（例：2026.11.02）
3. `CHANGELOG.md` の一番上に、変えたことを「- 」で始まる行で書く（利用者に伝わる言葉で）
4. コミットして、VERSIONと同じ名前のタグをつけて、プッシュする
   ```
   git add -A && git commit -m "2026.11.02 の更新"
   git tag 2026.11.02 && git push origin main --tags
   ```

## 知識を深める・新しい情報を拾う（imozuru）
知識（knowledge/）の土台を深めたい時は、同梱の imozuru（`.claude/skills/imozuru/`）で、原文までたどって調べる。2026-10-20 には「ESで企業は何を評価しているか」「企業の構造の読み方（人的資本の開示）」「経験を引き出す質問」の3本を調べ、04・07・12・13 と自分史インタビューの指示に反映した（調べた原文は、フォルダの中の `research/` に置く。GitHubには上げない。原文の再配布はしない）。
- 1本で約15〜20万トークン。3本を同時に回すと5時間の利用枠を使い切ったので、1〜2本ずつ回す
- 2週間ごとの更新の前に、見張りのモード（`/imozuru watch <話題>`）で、HR総研・就活の調査・採用の研究などの新着を拾い、知識に足すものを選ぶ
- 同梱した imozuru を新しくする時は、元のリポジトリ（MaryCache/imozuru）の skills/imozuru を上書きし、SKILL.md の先頭の「ES対策室での決まり」を残す

利用者側の動き：
- 有料版（Claude Code／Cowork）：起動時に前回の確認から3日以上たっていたら、自動で更新を取り込み、CHANGELOGの新しい行を本人に伝える。
- 無料版（Claude.ai）：本人が2週間に1回くらい GitHub の CHANGELOG を見て、新しい版ならダウンロードし直して、プロジェクトの指示と4つのファイルを差し替える（セットアップ手順書 3-5）。Claude.ai から GitHub の版を自動で確かめられるかは未確認なので、今は手動にしている。
- ChatGPT（自分史）：インタビューはほぼ初回だけなので、Claudeから更新の案内があったときに、指示を貼り直す。
