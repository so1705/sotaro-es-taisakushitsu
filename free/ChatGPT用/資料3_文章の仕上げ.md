# 【12_文章の仕上げ】

# 文章の仕上げ（v1 / 2026-10-20）

ESを出す前に、最後に必ずこの観点で書き換える。07（文体と盛り）の上に重ねる。
出典：stop-slop（Hardik Pandya, MIT License, https://github.com/hardikpandya/stop-slop）、yomiyasu（MIT License, https://github.com/nanaism/yomiyasu）。どちらもAIが書いた文章の目印を、人が読む言葉に戻すためのルール。ESに合わせて要点だけを取り込んだ。

## 1. カギ括弧を減らす
- 残すのは**人が実際に言った言葉**と、正式な名称だけ。1つの設問で、カギ括弧は多くても1組にする
- 強調のためのカギ括弧（「学生の成長」「なりたい姿」）は外す
- 発話も、2つ以上あるなら間接話法にする（「〜と言われ」「〜と話してくれました」）

## 2. 物や出来事を主語にしない（人を主語にする）
- 「一人ではできないことが動き出す」「あの瞬間が私を動かす」「データが教えてくれた」のように、物や出来事に人の動作をさせない。誰が何をしたかを書く
- 受け身の文は、動作をした人を主語にして書き直す

## 3. 演出の構文を使わない
- 対比の演出：「AではなくB」「AだけでなくB」「AよりB」。言いたいBをそのまま書く
- 否定を並べてから言う：「Aでもない、Bでもない、Cだ」
- 名言のような締め：「あの瞬間が私を動かしています」「〜が事業の出発点だと学びました」。事実か、その後の行動で終える
- 3つ並べ。2つで足りるなら2つにする

## 4. AIが好む語を、ふだんの言葉にする
| 見直す語 | ふだんの言葉の例 |
|---|---|
| 土台・入口・核心・主役・両輪・〜のカギ・〜の第一歩 | 何のことかを具体的に書く |
| 勝ち筋・刺さる・定石・別物・桁違い | うまくいくやり方・響く・いつものやり方 |
| 解像度・腹落ち・熱量・温度感・肌感・言語化・軸・落とし込む・紐解く | その語が指すことを、そのまま書く |
| 潰す・倒す・溶かす・踏み込む | 直す・選ぶ・費やす・詳しく調べる |
| 本質・本質的・等身大・泥臭い | 削るか、具体的に |
| 活用する・実施する・〜を図る・〜に資する・〜が可能です・担保 | 使う・行う・〜できます |
| 圧倒的・最前線・大きな価値・新たな価値を創出 | 数字や具体的な中身に置き換える |
| 想いを重ねる・場をつくる（何の場か書かない） | 誰と誰を、何でつないだかを書く |

## 5. 読点とリズム
- 短い主語のすぐ後の読点は外す（「私は、」→「私は」）。長い主語や節のあとは残す
- 同じ長さの文を3つ続けない。文末（〜ました）が4回続いたら、1つを変える
- 1文60字までは07のとおり

## 5-2. 人事がAIだと感じる2つ（採用担当503人の調査。04）
- **洗練されているのに、具体がない文**：表現はきれいなのに、場面・数字・固有の言葉（誰が・何と言った・何をどれだけ）が入っていない文。言い方を直すのではなく、経験DBの具体に置き換える。具体がなければ、その文は削るか、本人に聞く
- **整いすぎて、誰が書いても同じ完成度に見える**：どの設問も同じ型・同じ長さの文・同じ締め。本人の口癖や、少し不器用な言い回しを残す（経験DBの「本人の比喩・口癖」）

## 5-3. ESとしてあり得ない表現（話し言葉・方言）
自分史で集めた本人の言葉は、話し言葉のまま。ESに移す時は、必ず書き言葉に直す（07の3）。方言・タメ口・くだけた口調は、セリフの中でも残さない。「通過ESに載っていて違和感がないか」で判断する。

## 6. 書き換えの手順
1. カギ括弧を数えて、1〜2組まで減らす
2. 主語が物や出来事になっている文を探し、人を主語にする
3. 対比・否定の並べ・名言の締めを、言いたいことをそのまま書く形にする
4. 4の表の語を探して直す
5. 読点とリズムを直す
6. 5-2の2つを探す（洗練されているのに具体がない文・整いすぎ）
7. 字数を数え直す
意味・数字・事実は変えない。直すのは書き方だけ。

# 【03_落ちるES】

# 落ちるES：判定チェックリスト

1つでも当てはまれば指摘する。上ほど致命的。

## 致命的（これだけで落ちる）
- [ ] 他社名・他社の事業が混じっている
- [ ] 本人が承認していない新しい経験・数字がある（盛りは【盛り提案】として本人に出し、承認されたものだけ使う）
- [ ] 設問に答えていない（聞かれたことと別の話をしている）
- [ ] 指定字数の9割未満、または超過

## 埋もれる（通過ラインの下で横並びになる）
- [ ] 社名を他社に差し替えても通じる志望動機
- [ ] 冒頭を読んでも、何の話か分からない
- [ ] 判断の分岐（迷った選択肢と捨てた理由）がない
- [ ] 難しさが「大変だった」で終わっていて、どういう難しさか分からない
- [ ] 主語が「私たち」のままで、自分の貢献が切り出されていない
- [ ] 数字に比較の基準（前年比・母数・期間）がない
- [ ] 設問ごとに別の強みを書いていて、人物像が1つにまとまらない

## 面接で崩れる
- [ ] 「なぜ？」と3回聞かれたら答えられない文がある
- [ ] 本人が普段使わない言葉（難しい言い回し・ビジネス用語）が多い
- [ ] エピソードに登場する他の人の名前・役割・セリフが一つもない

## 不自然な日本語（07_文体と盛り の3）
- [ ] 口語（潰す・張りつく・〜してくれません）が混じっている
- [ ] 「〜ではなく〜」が1設問に2回以上ある
- [ ] 「・」でつないだ名詞が3つ以上、または1文に数字が3つ以上ある
- [ ] です・ます調とだ・である調が混ざっている

## AIっぽさ
- [ ] 抽象語が2つ以上続く（例：主体性と協調性を発揮し）
- [ ] よく見る言い回し：「〜という経験を通じて」「〜の重要性を痛感しました」「〜に貢献したいと考えております」
- [ ] 感情の描写が一つもない
- [ ] 三段構成がきれいすぎて、迷った跡や失敗が見えない

## 判定の出し方
- 致命的が1つでもあれば「落とす」
- 埋もれるが3つ以上なら「保留」
- それ以外は「呼ぶ」。ただし「面接で崩れる」がある場合は、面接でここを突かれると注記する

# 【00_本質原則】

# ESの本質原則

「結論ファースト」「数字を使う」「構造的に」は前提であって差別化にはならない。27卒では8割以上がAIでESを書いており、文章の巧拙では差がつかなくなった。差がつくのは以下。

## 1. ESは面接の予告編
- 面接官はESを見て質問を作る。ESの役割は「通過」と「面接で戦いたい土俵に誘導すること」の2つ。
- 全部を書き切らない。「なぜそう判断したのか」を聞きたくなる一文を、わざと1か所残す（例：「あえて〇〇はやめた」）。
- 逆に、聞かれたら困ることは書かない。面接で3段深掘りされても答えられない文は、ESの中で一番危ない文。

## 2. 評価されるのは「能力」ではなく「判断」
- 「主体性を発揮した」は誰でも書ける。書けないのは「AとBで迷い、〇〇だからBを選び、Aを捨てた」という分岐。
- 判断の分岐（捨てた選択肢と捨てた理由）が1つ入るだけで、ESは「その人にしか書けない文章」になる。
- 採用側は「入社後、同じ判断を自社の現場でしてくれるか」を想像している。

## 3. 成果の大きさより「難しさの説明」
- 小さい成果でも、なぜ難しかったかを構造で説明できれば評価される。難しさの型は3つ：
  - 利害の対立（立場の違う人が同じ方向を向いていない）
  - 資源の制約（時間・人・お金・権限がない）
  - 不確実性（正解がない、前例がない）
- 「大変だった」は感想。どの型の難しさかを書いて初めて、読み手が難易度を測れる。

## 4. 最初の2文で「誰か」が決まる
- 1枚にかけられる時間は短い。冒頭で何の話かが分かることが大事。（2026-10-20 改訂：以前の「冒頭2文に固有名詞・数字・意外性を入れる」は根拠が弱いので任意にする。通過ESの多くは「私の強みは〜です」のように普通に始まる）
- 冒頭には「固有名詞・数字・意外性」のどれか1つを入れる。「私の強みは〇〇力です」で始まる文章は、その時点で100枚の中に埋もれる。

## 5. 強みは企業の言葉に「翻訳」する
- 自分の言葉の強み（例：粘り強さ）を、その会社の行動指針・バリュー・社員インタビューに出てくる動詞に対応づける。
- ただし、企業の言葉をそのまま書き写すのは逆効果（媚びに見える）。エピソードの行動で見せて、言葉は1回だけ寄せる。

## 6. ES全体で人物像を1つにする
- 設問ごとに別の強みを書くと、人物像がぼやける。全設問を通して「この人は〇〇な人」と一文で言える状態にする。
- 設問ごとの役割分担：
  - ガクチカ＝行動の特性（どう動く人か）
  - 自己PR＝再現性（別の場面でも同じように動けるか）
  - 志望動機＝未来（その特性をこの会社で何に使うか）
  - 挫折＝自己認識（自分の弱さをどう扱う人か）

## 7. 志望動機は「原体験 × その会社にしかない手段」
- 理念への共感や、商品が好きという理由では差がつかない（全員が書く）。
- 「なぜこの会社か」は、会社の説明ではなく手段の違いで語る。事業の構造・業界内の立ち位置・持っている資産（顧客基盤・技術・拠点・データ）のうち、同業他社にないものを、自分のやりたいことの手段として選んだ、と書く。
- 「他社ではだめな理由」を、他社を下げずに書けるかが分かれ目。

## 8. 学びは、素直に書けばいい（2026-10-20 改訂）
- 通過ES・内定者ES 約55本の締めは、ほとんどが「この経験から〜を学んだ」「〜の大切さを学んだ」「〜力を培った」という素直な書き方だった。
- 以前このファイルにあった「学びは『以来〜している』という行動原理に変える」は、通過ESの分析より前に書いた根拠のないルールだったので撤回する。「〜するようになったのは、この時からです」のような締めは、上から目線で回りくどく読まれやすい。
- 学びの中身が、その会社の仕事で生きることが分かれば十分。

## 9. チーム成果は「自分の分」を切り出す
- 「チームで〇〇を達成した」だけだと、本人の貢献が見えない。
- 自分がいなかったら何が起きなかったか、を一文で書く。主語が「私たち」のままの文が続いたら危ない。

## 10. 数字には「比較の基準」をつける
- 「売上120%」より「前年比120%（過去5年で最高）」。母数・比較対象・期間がない数字は、読み手が評価できない。
- 表現や数字の見せ方を強くする「盛り」は、ESに必要な工夫。ただし、本人が面接で同じように話せないと崩れる。だから、盛りは必ず本人に提案して、本人が決める（07_文体と盛り）。

## 11. インターンESと本選考ESは別物
- インターンでは、完成度よりも伸びしろ・学習意欲・その仕事への仮説を見ている。
- 「インターンで何を得たいか」は「成長したい」ではなく、「〇〇という仮説を、△△の場面で確かめたい」の形にすると強い。
- 本選考では入社後の具体像（配属・職種・最初の3年）まで求められる。

## 12. 字数ごとの設計
- 200字：1エピソード・1論点。判断の分岐は1つだけ。
- 400字：判断を1つ深く掘る（なぜその判断か、どう周りを動かしたか）。
- 600〜800字：変化を2段階で書く（最初のやり方が失敗し、やり方を変えた）。
- 指定字数の9割未満は「意欲が低い」と読まれやすい。

## 13. AIで書いたことを隠すより、AIっぽさを消す
- AI文章の特徴：抽象語の連続、どこかで見た言い回し、感情と固有名詞の欠落、きれいすぎる三段構成。
- 消し方：その場のセリフ、その時の感情、固有の場所・人の役割、迷った瞬間を入れる。これらはAIには書けず、経験DBにしかない。
