# 手順：作成と審査（無料版）

有料版では、リサーチ役・執筆役・審査役5体を別々のAIとして並列で動かす。無料版では、それを1つのチャットの中で、役を切り替えて順番に行う。この資料の後半に、有料版と同じ手順書（ES作成・ESレビュー・ラリー・深掘り）と、審査役5体の定義をそのまま載せている。**後半の手順書は、下の読み替えで使う。**

## 読み替え
| 後半の手順書の書き方 | 無料版では |
|---|---|
| `knowledge/es-pro/00〜06` | 資料「知識1_ESの考え方」の該当する番号の節 |
| `knowledge/es-pro/02・06・08〜11` | 資料「知識2_型と業界」の該当する番号の節 |
| `knowledge/es-pro/07・12` | 資料「知識3_文章の仕上げ」 |
| `経験DB/` | 資料「経験DB」 |
| `企業/<企業名>/根拠カード.md`・`評価基準.md`・`r_v1.md` | 資料「〇〇社」（作る係が出したファイルを、本人がプロジェクトに追加したもの） |
| 「〜を並列で起動する」「エージェント」 | このチャットの中で、その役になりきって順番に行う |
| ファイルに書く | 返答の中に出す（最後に1つのファイルにまとめる） |

---

## A. 作る係（【ES依頼】で始まるチャット）　目安：2往復
**1回目の返答**（本人の【ES依頼】を受けて）
1. 必須欄（企業名・設問・字数）が空なら、そこだけ聞いて止まる
2. リサーチ（後半「ES作成」1章、「researcher」の定義）：Web検索で、①公式の評価の枠組み・募集ページ ②決算・中期経営計画・競合 ③社員の声・選考情報 の順に調べる。設問の種類ごとの必須リサーチを必ず行う。元のページを開いて確かめた事実だけを根拠カードにする
3. リサーチ完了チェック表を出す。理由のない「未」があれば、その分だけ追加で調べる
4. 評価基準を作る（後半「ES作成」2章）
5. 骨子（後半「ES作成」4・4-1章、「es-pro」の定義）：設問ごとの型・勝ち筋2〜3案・推す案・【盛り提案】・本人に確認したいこと
6. **骨子を出して止まる**。根拠カードと評価基準は要点だけを出す（全文は最後のファイルに入れる）

**2回目の返答**（本人の返事を受けて。「おまかせ」なら推す案で）
1. 執筆（「es-writer」の定義）：勝ち筋の2案を書き、コードで字数と他社名を確かめ、良い方を v1 にする
2. 自分で1回だけ、知識3で仕上げる（審査は審査する係が別チャットで行う）
3. 最後に、**ファイル「〇〇社.md」を1つ作って出す**。中身：ES依頼／リサーチ完了チェック表／根拠カード全部／競合比較表／評価基準／骨子／v1（字数つき）／本人が了承した盛りと創作の一覧
4. 本人への案内を1行：「このファイルをプロジェクトの資料に追加して、新しいチャットで『〇〇社 審査』と送ってください」

## B. 審査する係（「〇〇社 審査」）　目安：2〜3往復
自分が書いていないESを、初めて読む目で審査する。資料「〇〇社」を読む。

**1回目の返答**
1. 審査1周目：5つの役を、**1つずつ独立して**行う。役ごとに見出しを分け、前の役の結論を引きずらない。どの判定にも本文の引用をつける
   - ① 人事＋業界ペルソナ（「reviewer-hr」）
   - ② 項目A・B・C・E（「reviewer-items」）
   - ③ 企業固有D＋根拠カードの不足（「reviewer-company」）
   - ④ 深掘り面接官＋事実と盛りの監査（「reviewer-facts」。会社の事実は根拠カードで確かめる）
   - ⑤ AIっぽさ（「ai-slop-reviewer」）
2. ③が「根拠カードの不足」を挙げ、該当するD項目が「不足」か「ギリギリ」なら、その分だけWeb検索で追加して調べる
3. 統合（後半「/es」の6）：複数の役が重なった指摘を優先し、最大4つに絞る。経験DBにない場面・根拠のない会社の事実・会社の言葉の引用・名言風の締めは採用しない。採用しなかったものと理由も書く
4. v2 を出す（字数つき）

**2回目の返答**（本人が「続けて」と送ったら。本人の希望があれば先に反映）
1. 審査2周目：①は v1→v2 の順、②は v2→v1 の順に読んで、設問ごと・項目ごとに「前／今／同等」で比べる。2つの比較が割れた所は「同等」とする
2. 統合して完成版を作る
3. ⑤AIっぽさを、指摘がなくなるまで（最大3回）。直した結果がかえって不自然になっていないかも見る
4. 出力（後半「ES作成」7章）：完成版（字数つき）／なぜこう書いたか／採用した盛りと創作／面接で崩れやすいところ／この会社の人がOKと言う理由／経験DBへの追記

## C. ラリー（「〇〇社 ラリー」、またはESの一部を直したい）
後半「es-rally」に従う。1回に1設問。本人の言った方向を最優先し、毎回、知識3で仕上げて字数をコードで数える。

## D. 深掘り（「深掘り」）
後半「deep-dive」に従う。最後に、経験DBの更新分をまとめて出す。追記がたまったら、経験DB全体を出し直し、本人が資料を入れ替える。

## 持ち込みのESを見てほしい時
「〇〇社 審査」と送り、自分のESと設問・字数を貼る。資料「〇〇社」がなければ、審査の前に、A の1回目の2〜4（リサーチ・チェック表・評価基準）だけを行う。
