# ES作成（v1まで）

必須欄（企業名・設問）が空のときと、**骨子を見せるとき（4章）**だけ止まる。それ以外は止まらずに進める。途中経過はチャットに長く出さず、工程の名前を1行ずつ伝えるだけにする。

良いESは、本人の「意図」「方向」「ロジック」から生まれる。AIは、素材を集め、選択肢と根拠を出し、文章に仕上げる編集者に徹する。

## 0. 読むもの
- `knowledge/es-pro/` の 00〜07（判断の軸。特に 05 線の設計図、06 通過ES分析、07 文体と盛り）
- 経験DB（無料版：プロジェクトの `経験DB.md`＋プロジェクトのメモリにある経験DB追記／有料版：`経験DB/`）
- **本人が過去に書いたES・自己PR・志望動機**（あれば必ず）：本人の文体、すでに使っている表現と数字、将来ビジョン。経験DBにない強い素材が入っていることが多い。同じエピソードを他社にどう書いたかも確認し、矛盾を避ける

## 1. リサーチ → 根拠カード
`docs/DESIGN.md` 4章の8カテゴリを順に調べる。公開されている情報だけ（ログインが必要なサイトは自動で取りにいかない。本人が備考に貼ったものは使う）。
- 1つの事実＝1枚の根拠カード：`[C-番号] 主張／出典URL（種類：公式・報道・社員の発信・体験記）／引用（短く）／効く評価項目`
- 止める基準：そのカテゴリで、連続3件読んで新しい傾向が出なくなったら次へ。**各カテゴリで「読んだ件数」と「止めた理由」を網羅チェック表に書く**。検索結果の要約だけで済ませたものは「未確認」とし、ESの根拠にするものは必ず元のページを開く。
- **設問の種類ごとの必須リサーチ**（08 設問タイプ別の型）。これが済むまで評価基準に進まない：
  - 志望動機：その会社にしかない具体名（事業・商品・技術・地域・開発思想）を3つ以上、同業他社との違いと一緒に
  - インターン・コース・部門の志望理由：①そのインターン（部門）のページを開き、テーマ・期間・内容・成果物・社員の関わりを確認 ②その事業の今（伸びている所・課題）を決算・ニュースで確認 ③過去の参加者の声（公開されているもの・本人の備考） ④どのインターンに出すか本人が決めていなければ、募集中のものから本人の経験と一番つながるものを、理由つきで推す
  - ガクチカ・自己PR：会社の求める人物像・行動指針（公式）
  - **すべての設問で最初に**：その会社の公式の評価の枠組み・行動指針を探す（09の4）。あれば評価基準のD項目にする
  - **志望動機・なぜ当社か**：同業の主要2〜4社との競合比較表を作る（09の2）。「省略」にしない
  - **意見・提案型の設問**（取り組むべき事業・社会の課題・新しい売り方・10年後など）：09の1の工程（事実 → 論点の候補3つ → 誰でも思いつくものを捨てる → 本人ならではの視点 → 会社の資産を使う）
  - **字数が200字以下の設問**：09の3の圧縮の工程（入れる言葉を3つ先に決める）
- 重み：公式 ＞ 報道 ＞ 社員の発信 ＞ 体験記・まとめ。根拠が1件だけの傾向は「仮説」と書く。
- 保存先：有料版 `企業/<企業名>/根拠カード.md`／無料版 チャットの中で作り、6の最後に評価基準と一緒にファイルで出す。

## 2. 評価基準（作ったら固定）
`docs/DESIGN.md` 5章のテンプレートで `評価基準.md` を作る。
- 足切り／A 人柄／B 熱意／C 可能性／D 企業固有（根拠カードから最大5つ。A〜Cのどれに属するかを書く）／E 本人性・深掘り耐性／F 読みやすさ
- 各項目に4段階（不足／ギリギリ／十分／突出）の具体例を書く。
- 設問ごとの重み：01 設問の裏読みと、05 の「設問ごとに線のどの区間を見せるか」から決める。
- 「突出」の具体例は、10（トップ層の校正）の5を目安に書く。会社の種類でESの重みが違う（10の1）ので、外資戦略・外銀は端的さと面接の核を、総合商社・日系大手は設問全体の線と事業の視点を重く見る。**総合商社では「事業の視点（収益・事業性・市場の構造）で経験を語れているか」を企業固有の項目に必ず入れる**（10の2）。
- **設問の種類ごとの必須項目**：志望動機には「会社固有の具体名で、なぜこの会社かを言えているか」、インターン・コース・部門の志望理由には「そのインターン（部門）の中身と、自分の経験・足りないもの・確かめたいことがつながっているか」を、必ず評価項目に入れる（08）。
- 一度作ったら変更しない。本人が情報を足したときだけ次の版にする。

## 3. 方針審査（本人の書き方メモがあるときだけ）
1. AIの方針を、メモを見ずに先に作る。
2. 本人の方針と並べ、「方針X／方針Y」とだけ書いて、どちらが誰の案か分からない状態で、評価基準に照らして比べる（順番を入れ替えて2回）。
3. 採用／補強して採用／一部採用／不採用 のどれかに決め、評価基準と根拠カードを理由に書く。不採用でも、本人が希望すればそれで書き、リスクを残す。

## 4. 骨子を見せて、本人が方向を決める（ここだけ止まる）
設計（下の4-1）を終えたら、文章を書く前に、設問ごとの骨子をチャットに出す。
```
【骨子】Q1（字数）
- 使うエピソード：〇〇（候補：A／B。Aを推す理由1行）
- 流れ：一言で → 壁 → 反省・切り替え → 打ち手 → 結果 → 培った力（各1行）
- 使う数字：〇〇・〇〇
- 盛り提案：（あれば 07 の形式で）
- 決めてほしいこと：（あれば1〜2個）
```
本人が「この方向で」「ここはこのロジックで」と返したら、それを最優先して執筆に進む。本人が「おまかせ」と言えば推した案で進む。

## 4-1. 設計（es-pro の仕事1）
**最初に、設問ごとに型を1つ選ぶ**（11_型ライブラリの1「型の選び方」）。本人の素材の性質と、書きたい内容に合わせる。06・08・10の型は評価基準ではなく、選ぶための引き出し。評価基準の項目は増やさない。どの型でも、11の0「外せない核（7つ）」は入れる。
`.claude/agents/es-pro.md` の「仕事1」に従って `design.md` を作る。特に：
- 設問ごとに、線のどの区間を見せるか（05）
- エピソード候補を3つ比べて1つに絞る（評価基準との一致度／判断の分岐があるか／深掘りに耐えるか）
- その原体験・エピソードが、他の就活生と似通っていないか（06 発見9）。似ているなら、本人にしかない場面・人・言葉を経験DBから探す
- ES全体の人物像を一文で。設問どうしで同じ強みを繰り返さない

## 5. 執筆
- 有料版：勝ち筋を変えた3案を並列で（例：A人柄で勝負／B熱意で勝負／D企業固有で勝負）。無料版：2案。
- 文体は 07 と、本人の過去のESに合わせる（です・ます調／だ・である調も本人に合わせる）。
- 事実と数字は、経験DB・本人の過去のES・本人の発言にあるもの、または本人が承認した盛りだけ。AIが黙って新しい経験や数字を足さない。
- 字数は指定の9割以上・上限以下。

## 6. 審査 → 統合 → 書き直し
`docs/DESIGN.md` 6章の5層で審査する。
1. 機械チェック（コードで）：字数・他社名・禁止表現（03 のAIっぽさの言い回し）
2. 事実監査：ESを主張の単位に分け、経験DB・過去のES・本人の発言と照らして「根拠あり／承認済みの盛り／未承認」。未承認があれば、【盛り提案】として本人に出すか、元の事実に戻す
2-2. 日本語の自然さ：03 の「不自然な日本語」と 07 の「避けること」で確認する
3. 項目審査：A〜Fを担当制で。判定には本文の引用を必須にする。案は「案X・案Y」とラベルを伏せて審査する
4. 全体の印象：業界ごとの3人のペルソナが「面接に呼ぶか」を判定。項目審査と食い違ったら理由を書く
5. 一貫性：設問どうし、過去に出したESとの矛盾
統合：一番良い案を選び、書き直し指示を「重み×不足の大きさ」の順に最大3つ → 書き直す → 変えた項目と、他の項目が下がっていないかを再審査。合格ライン（足切りなし・重い項目がすべて「十分」以上）に届くまで（有料版は最大3周、無料版は1〜2周）。

## 7. v1 を出す（チャットに出すのはここだけ）
```
【v1】〇〇社 ／ 設問ごとに本文と（N字）
【なぜこう書いたか】設問ごとに3行以内：見せた線の区間・選んだエピソードと理由・効かせた評価項目（根拠カード番号）
【評価】項目ごとの段階（突出／十分／ギリギリ）だけ。詳細は折りたたむ
【面接で聞かれそうなこと】2〜3個
【なぜこの会社の人がOKと言うか】会社の公式の基準（根拠カード番号）と、ESの文を1対1で対応させて3〜5行
```
- 想定問答（各文に「なぜ？」を3段）と一貫性の表（09の5）は、ファイルに保存する（有料版：`企業/<企業名>/面接想定.md`）。チャットには、崩れやすい場所の警告だけ出す。
- 経験DBに素材がなくて、それ以上良くできなかった箇所があれば、そこだけ本人に1〜2問聞く。
- 深掘りしたら良くなりそうな箇所・新しく出てきた事実は、**チャットに書かずに**記録する（無料版：プロジェクトのメモリに「深掘り候補」として／有料版：`経験DB/_深掘り候補.md`）。
- 有料版は `企業/<企業名>/` に、根拠カード・評価基準・design・各案・審査結果・v1 を保存する。無料版は、評価基準.md をファイルで出して「プロジェクトに追加してね」と一言添える（審査チャットで使うため）。
