# 持ち込みESのレビュー（パターンB）

0から作るとき（es-create）との違いは、**本人の書いたESを土台にする**こと。本人の文体と、すでに選んだエピソードを尊重し、壊さずに引き上げる。

## 0. 準備（足りないものだけ作る）
- 設問と字数：本人に聞く（ESと一緒に貼ってもらう）
- 企業の根拠カードと評価基準：なければ es-create の1〜2章で作る（すでにあれば使う）
- 経験DB・本人の過去のES：読む

## 1. 1周目の審査（独立して）
有料版はサブエージェントを並列で起動する。無料版は、同じ審査の観点を順番に、ラベルを伏せて行う。各審査役は、ファイルを読むだけで、書き換えはしない。
| 審査役 | 見るもの | 返すもの |
|---|---|---|
| 一次選考の人事 | 1枚90秒で読んだ印象 | 呼ぶか／冒頭2文の人物像／印象が落ちた箇所2つ／書き換え案2つ |
| 項目審査（A〜C） | 判断の過程・動機・再現性 | 4段階の判定（本文の引用つき）／突出に上げる書き換え案3つ |
| 企業固有の審査 ×2（独立） | D1〜D5 | 4段階の判定（引用と根拠カード番号）／書き換え案2つ |
| 深掘り面接官＋盛り監査 | なぜを3回重ねて詰まる文／経験DBにない主張 | 想定質問と書き方の変え方／【盛り提案】2つ |
| 日本語・文体の監査 | 07・03 の基準 | 不自然な箇所と書き換え案（字数を増やさない）5つ |
| 業界ペルソナ（事業責任者など） | 直感 | 一緒に働きたいか／おっと思った点・薄い点／一気に評価が上がる要素1つ |
各審査役への指示は短くし、返答の字数の上限を決める（400〜500字）。

## 2. 統合（親が行う）
1. 企業固有の審査2体の判定が割れた項目は、両方の理由を読んで決める。
2. 複数の審査役が同じ箇所を指摘していれば、優先度を上げる。
3. 書き直し指示を「設問の重み×不足の大きさ」の順に並べ、**1周につき最大3〜4つ**に絞る。全部直すと文章が崩れる。
4. 盛りの提案は【盛り提案】として本人に見せる。デモンストレーションなど本人が仮置きを許した場合は、採用して印をつける。
5. 書き直す。字数はコードで数える。本人の文体（07）を保つ。

## 3. 2周目の審査
書き直した版を、1周目と同じ審査役（有料版は新しいサブエージェント）で審査する。加えて：
- 1周目の版と2周目の版を、項目ごとにどちらが良いか比べる（順番を入れ替えて2回、食い違ったら「同等」）。
- 書き直しで下がった項目がないかを確認する。
統合 → 書き直し（最大3つ）→ 完成版。

## 4. 本人への返し方
```
【完成版】（設問ごとに本文と字数）
【1周目→2周目で何が変わったか】設問ごとに2〜3行
【採用した盛り】あれば
【面接で聞かれそうなこと】2〜3個
```
審査の詳細は、ファイル（有料版：`企業/<企業名>/reviews_rN.md`）に残し、チャットには出さない。その後は es-rally で本人と仕上げる。
